## 二、关键实现提炼（可用于工程落地）

### 核心数据结构
```text
LCSObject { LCSseq: List[token], lineIds: Set[int] }
LCSMap:   List[LCSObject]
PrefixTree: 索引所有已知消息类型（token 序列）
```

### 主流程（每条日志 e）
1. 用分隔符切分 `e` → token 序列 `s`；`n = len(s)`；`τ = n/2`
2. **前缀树查找**：逐 token 沿树走，未被匹配的 token 记为参数；若匹配的 `stri` 长度 `≥ τ` → 命中，更新对应 LCSObject 的 `LCSseq`，加入行号
3. 否则 **简单循环**：遍历 LCSMap 各 `qi`，双指针判断 `qi` 是否为 `s` 子序列，记录满足条件且 `|LCS|≥τ` 者（并列取 `|qi|` 最小）
4. 仍无命中 → 遍历所有 `qi`，先算 **Jaccard**，`Jaccard>0.5` 者再算 LCS；若 `|LCS(qi,s)|>τ` 则回溯生成新 `LCSseq`（不一致处标 `*`，相邻 `*` 合并），更新对象与树；否则 `e` 作为**新消息类型**新建 LCSObject 并插入树
5. **回溯生成 LCS 序列**：标准 LCS DP + 回溯，在分歧位置插入 `*`

### 关键参数
- 消息类型阈值 `τ = 0.5`（即 `|s|/2`）
- 预过滤失败率 < 0.1%，naive LCS 仅用于 < 0.1% 日志

### 性能要点
- 99%+ 的日志在前缀树 / `O(n)` 内完成
- LCSMap 大小有界（≤ 实际消息类型数 m，常数级）
- 单条查找摊还 `O(n)`，实测毫秒级

### 与离线法对比结论
Spell 准确率更高（尤其大规模异构日志），且能在线流式处理，无需离线预训练或源码/正则。
